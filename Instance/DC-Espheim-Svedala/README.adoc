== Introduction

This README complements the machine-readable link:https://github.com/entsoe/relicapgrid/blob/cgmes-3.0_ncp-2.4_tc-1.1/Instance/DC-Espheim-Svedala/Grid/manifest.ttl[manifest] and provides a human-readable description of the **DC Espheim–Svedala HVDC Interconnector Model** within the *ReliCapGrid* repository.

The DC Espheim–Svedala model is a synthetic HVDC interconnector model created for testing, demonstration, and interoperability purposes.
It does not represent a real HVDC link.

This model describes the high-voltage direct current (HVDC) link connecting the Espheim and Svedala control areas.
It is modelled as a separate dataset alongside the individual IGMs of the connected TSOs.

The model is compliant with the *IEC Common Grid Model Exchange Standard (CGMES)*, as well as *ENTSO-E Network Code data exchange specifications* (profiles).
The datasets are validated with SHACL constraints available in link:https://github.com/entsoe/application-profiles-library[ENTSO-E Application Profiles Library] repository and are subject to review by the ENTSO-E Standard Vetting Interoperability Tests (SV-IOP).

== Model Scope and Content

The DC Espheim–Svedala model includes datasets organised into the following folders:

* *Grid* – Static and operational grid model datasets for the HVDC link, covering the following CGMES profiles:
** EQ – Equipment
** TP – Topology
** SSH – Steady-State Hypothesis
** SV – State Variables

* *NetworkCode* – Network Code profile datasets, covering:
** CO – Contingency
** RA – Remedial Action

* *GridSituation* – Planned for future development; will describe specific operational snapshots of the HVDC link.

* *ChangeSet* – Planned for future development; will contain incremental model updates (deltas) representing objects added, modified, or deleted relative to a base model.

== Purpose and Intended Use

The DC Espheim–Svedala model is intended for:

* Interoperability and conformance testing of HVDC model exchange
* Toolchain validation (import/export, HVDC profile support)
* Training, documentation, and demonstration purposes

== Package Structure and Serializations

The package is provided in multiple serializations:

* `cimxml/` – According to *IEC 61970-552:2016* which is the main serialization used for *IEC 61970-600-1* (CGMES) datasets and for ENTSO-E Network Code profiles.

* `jsonld/` –
  CIM JSON-LD representations aligned with *IEC 61970-553* (under development), enabling integration with semantic and data-driven tooling.
  This serialization is not currently provided and may be added in the future. (CIM JSON-LD is generated from CIMXML.)

* `trig/` – link:https://www.w3.org/TR/trig/[TriG] representation for improved readability and semantic inspection. (TriG is generated from CIMXML.)
